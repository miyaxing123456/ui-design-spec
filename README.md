# ui-design-spec

把一张 UI 设计稿（截图 / 图片 / **Figma / 蓝湖等设计稿链接**）转成**前端能直接照着写代码的规范**。核心工作方式是**提问驱动**：不一次性套模板，而是通过与用户多轮问答收敛分析方向，只深挖用户关心的板块，其余标「略过」。

> 生成方向：分析界面 / 生成前端规范 / 复刻界面 / 拆组件 / 定响应式方案。也适用于把设计稿转换成**可落地代码**。

## 特性

- **多输入形态**：支持设计稿**图片/截图**，也支持 **Figma / 蓝湖等公开设计稿链接**——优先尝试直接读链接，读不全时如实告知并回退到让用户给截图/切图/token。
- **提问驱动**：先问清楚（类型 / 响应式 [A] / 宽高 [B] / 视口 [C] / 交付目标 / 重点关注 / 工程环境），再定向输出，而不是套固定模板。
- **必问清单 + 告知影响**：文字超长（是否要 tooltip）、图片固定宽高 vs 宽高比、表格列宽/固定列、元素数量可能多时的滚动策略（是否整页滚、是否多滚动条）、组件拆分（复用驱动不过度拆 + 拆分结果让用户确认）——这些实战高频坑，都会问用户并给出方案与影响。
- **精确 token**：颜色**尽量精确采样**给 `#HEX`，并标注采样偏差、列入待确认项供用户核对。
- **可落盘产物**：支持把 token / 规范导出成 `tokens.css` / `tokens.json` / `DESIGN.md`，进项目直接复用。
- **质量自检清单**：定稿前逐项打勾，保证结论都来自用户确认、无默认拍板。
- **覆盖面**：后台 / C端 / 信息流，通过决策矩阵区分，不因界面类型硬编码单位选型。

## 安装

放到 Claude Code / 兼容 agent 的 skills 目录（如 `~/.claude/skills/ui-design-spec` 或 `~/.agents/skills/ui-design-spec`），下一会话自动发现。

```bash
# 示例
mkdir -p ~/.claude/skills
git clone <你的仓库> ~/.claude/skills/ui-design-spec
```

## 用法

给 agent 一张设计稿图 / 一个设计稿链接 + 一句「用 ui-design-spec 分析这个」，流程为：

0. **获取设计稿** —— 图片/截图直接读；设计稿链接优先 web_fetch，读不全回退要图
1. **冷启动提问** —— 类型 / [A] 响应式 / [B] 宽高 / [C] 视口 / 交付目标 / 重点关注 / 工程环境
2. **类型判定** —— 从回答映射到决策矩阵
3. **定向深挖** —— 只对圈定板块输出（其余「略过」）
4. **迭代补问** —— 超长 / 图片 / 表格 / 滚动等必问点逐一确认
5. **定稿** —— 决策清单 + Token 表 + 结构图 + 组件树 + 质量自检（可选落盘产物文件）
